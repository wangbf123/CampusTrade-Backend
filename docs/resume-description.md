# 简历项目描述

## 项目名称

CampusTrade：基于 Spring Boot 的校园二手交易与预约履约平台

## 一句话介绍

该项目面向校园闲置物品交易场景，提供商品发布、浏览搜索、交易预约、订单状态流转、超时取消、站内通知、热门商品榜单、接口限流和防重复提交等能力，重点解决预约履约过程中的状态一致性、热点访问、异步通知和接口风控问题。

## 技术栈

```text
Spring Boot、Spring MVC、MyBatis-Plus 预留、MySQL、Redis、RabbitMQ、
Spring AMQP、Docker Compose、springdoc-openapi、JUnit、Maven
```

## 简历版描述

```text
CampusTrade：基于 Spring Boot 的校园二手交易与预约履约平台

项目面向校园闲置物品交易场景，提供商品发布、商品检索、交易预约、订单状态流转、超时取消、站内通知和热门商品榜单等功能。系统通过订单状态机限制非法状态流转，并在卖家确认预约时使用商品状态条件更新保证并发场景下只有一个预约成功；使用 Cache Aside 模式缓存商品详情，对不存在商品写空值缓存，并通过 Redis ZSet 实现热门商品榜单和超时订单队列；基于 RabbitMQ + Outbox 解耦订单状态变更与站内通知，使用 eventId 保证消费者幂等；通过 Redis INCR/EXPIRE 实现接口限流，并使用 SET NX EX 防止预约接口重复提交。
```

## 简历亮点

```text
- 设计预约订单状态机，限制 PENDING、CONFIRMED、COMPLETED、CANCELLED、EXPIRED 等状态的非法流转，并通过 `WHERE status = ?` 条件更新避免并发确认、重复取消等状态错乱问题。
- 使用 Cache Aside 模式实现商品详情缓存，对不存在商品写入短 TTL 空值缓存，并通过随机过期时间降低缓存穿透和雪崩风险。
- 基于 Redis ZSet 实现热门商品榜单和超时订单队列，定时任务仅拉取到期订单 ID，减少全表扫描压力。
- 基于 RabbitMQ + Outbox 实现订单通知异步化，订单状态变更只写 Outbox 事件，后台任务异步发布，并通过 eventId 唯一键保证消费者幂等。
- 使用 Redis INCR/EXPIRE 实现登录、预约、订单操作等接口限流，并通过 X-Idempotency-Key + SET NX EX 防止预约接口重复提交。
```

## 面试开场白

```text
这个项目不是完整电商系统，我刻意没有做购物车、支付和物流，而是围绕校园线下交易的真实流程做了一个预约履约平台。核心难点在于预约订单的状态一致性、热门商品访问、超时自动取消、状态变更通知以及防重复预约。所以项目重点做了订单状态机、Redis 缓存和 ZSet 队列、RabbitMQ + Outbox 异步通知，以及接口限流和幂等控制。
```

## 不建议这样写

下面这种写法太普通，尽量避免：

```text
实现了用户登录、商品管理、订单管理、消息通知等功能。
```

原因是它没有体现后端设计能力，也无法引导面试官追问你擅长的技术点。
